# Специфікація діаграми послідовності

## UC-05 — Оформити оренду


### Мета

Описати взаємодію між користувачем та компонентами системи під час оформлення оренди автомобіля, зокрема успішне створення оренди та обробку випадків, коли користувач не авторизований або автомобіль недоступний на обраний період.

### Учасники обраної взаємодії

- **User (Customer / Guest)** — користувач системи: авторизований користувая(клієнт) або не авторизований користувач(гість).
- **iCARus UI** — інтерфейс взаємодії з користувачем.
- **RentalService** — координує процес оформлення оренди.
- **AvailabilityService** — перевіряє доступність автомобіля на обраний період.
- **PricingService** — розраховує загальну вартість оренди.
- **RentalRepository** — зберігає створену оренду.

**Уточнення:**  `iCARus UI`, `RentalService`, `AvailabilityService`, `PricingService`, `RentalRepository` — ці учасники не були окремо представлені в діаграмах попередніх лабораторних робіт, вони додані для деталізації сценаріїв UC-05 у межах завдання №3.

### Сценарії

#### G-1 — Успішне створення оренди доступного автомобіля

**Передумови:** користувач авторизований та обраний автомобіль доступний на вказаний період.

1. Customer надсилає через iCARus UI запит на оформлення оренди на певний період з автомобілем, який він обрав.
2. iCARus UI передає запит до RentalService для оформлення оренди.
3. RentalService перевіряє доступність автомобіля через AvailabilityService.
4. AvailabilityService повертає результат перевірки.
5. RentalService запитує у PricingService розрахунок загальної вартості оренди.
6. PricingService повертає загальну вартість оренди за увесь період.
7. RentalService формує оренду зі статусом "запланована" та передає її до RentalRepository.
8. RentalRepository зберігає оренду й повертає результат.
9. iCARus UI повідомляє Customer про успішне оформлення оренди.

**Результат:** створено оренду зі статусом "запланована", збережено дані про клієнта, обраний автомобіль, період оренди і загальну вартість оренди за увесь період.

#### G-2 — Гість намагається створити оренду (йому буде відмовлено)

**Передумови:** користувач не авторизований.

1. Guest надсилає через iCARus UI запит на оформлення оренди.
2. iCARus UI передає запит до RentalService для оформлення оренди.
3. RentalService перевіряє, чи є користувач авторизованим.
4. RentalService повертає результат, що користувач не авторизований.
5. iCARus UI пропонує Guest зареєструватися або увійти в обліковий запис.

**Результат:** оренду не створено і користувачу запропоновано реєстрацію або вхід в систему iCARus.

#### G-3 — Автомобіль недоступний на обраний період (відмова через перетин періодів оренди)

**Передумови:** користувач авторизований і для цього автомобіля існує активна або запланована оренда, період якої перетинається з періодом, обраним клієнтом.

1. Customer надсилає через iCARus UI запит на оформлення оренди на певний період з автомобілем, який він обрав.
2. iCARus UI передає запит до RentalService для оформлення оренди.
3. RentalService перевіряє доступність автомобіля через AvailabilityService.
4. AvailabilityService виявляє перетин з іншою активною або запланованою орендою та повертає негативний результат.
5. RentalService відхиляє запит на оформлення оренди.
6. iCARus UI повідомляє Customer, що автомобіль недоступний на обраний період.

**Результат:** нову оренду не створено і користувач отримав повідомлення про недоступність автомобіля на обраний їм період.


### Критерії узгодженості

- Успішне оформлення створює оренду зі статусом "запланована".
- Користувач не може створити оренду без авторизації. в цьому випадку йому пропонується реєстрація або вхід.
- Активні та заплановані оренди блокують перетинні періоди для того самого автомобіля.
- Скасовані та завершені оренди не блокують доступність автомобіля.
- Загальна вартість оренди (`Rental.price`) розраховується на основі стандартного денного тарифу моделі автомобіля (`CarModel.dailyRate`) та тривалості оренди.
