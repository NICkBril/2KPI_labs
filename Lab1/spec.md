# spec   iCARus

# 1. Намір
Побудувати логічну модель даних для автоматизації прокату авто «iCARus». Модель має охоплювати облік бази клієнтів, каталог автопарку 
(з деталізацією за моделями та технічними характеристиками), процес оформлення та обліку оренд, а також повний облік платежів і розрахунків.

# 2. Сутності та атрибути

1. **Customer (Клієнт)**
   - `id` *[PK, string]*: Ідентифікатор клієнта
   - `firstName` *[string]*: Ім'я
   - `lastName` *[string]*: Прізвище 
   - `email` *[string]*: Електронна пошта 
   - `phone` *[string]*: Номер телефону
   - `address` *[string]*: Місце проживання

2. **Rental (оренда)**
   - `id` *[PK, string]*: Ідентифікатор оренди авто
   - `customerId` *[FK -> Customer.id, string]*: Ідентифікатор клієнта
   - `carId` *[FK -> Car.id, string]*: Ідентифікатор машини
   - `startDate` *[date]*: Дата початку оренди
   - `endDate` *[date]*: Дата закінчення оренди
   - `price` *[number]*: Загальна ціна оренди
   - `status` *[string]*: Стан оренди (активна, завершена, скасована, запланована)

3. **Car (Машина)**
   - `id` *[PK, string]*: Ідентифікатор машини 
   - `modelId` *[FK -> CarModel.id, string]*: Ідентифікатор моделі авто
   - `status` *[string]*: Стан доступності авто (в оренді(зайняте), вільна, на обслуговуванні, недоступна)


4. **CarModel (Модель машини)**
   - `id` *[PK, string]*: Ідентифікатор моделі авто
   - `brand` *[string]*: Марка машини ("BMW", "Toyota", ...)
   - `model` *[string]*: Модель авто ("X5 G05", "Land Cruiser 300", ...)
   - `category` *[string]*: Категорія (легкова, кросовер, ...)
   - `description` *[string]*: Опис авто
   - `dailyRate` *[number]*: Фіксована стандартна ціна оренди за один день

5. **Payment (Оплата)**
   - `id` *[PK, string]*: Ідентифікатор оплати
   - `rentalId` *[FK -> Rental.id, string]*: Ідентифікатор оренди авто
   - `amount` *[number]*: Сума конкретного платежу
   - `paymentDate` *[date]*: Дата здійснення платежу
   - `status` *[string]*: Стан платежу (сплачено, скасовано, очікується підтвердження)



# 3. Зв'язки

- `Customer` 1 to N `Rental`: Один клієнт може мати декілька оренд (взяти в оренду декілька машин, де окрема оренда стосується однієї машини).
- `Car` 1 to N `Rental`: Одна оренда може стосуватись тільки однієї машини, проте один автомобіль може мати багато оренд у різний час.
- `CarModel` 1 to N `Car`: Одна модель може бути пов'язана з декількома автомобілями.
- `Rental` 1 to N `Payment`: Одна оренда може бути розділена на декілька оплат.




# 4. Критерії прийняття
- Кожен клієнт, автомобіль, модель автомобіля, оренда та оплата мають власний `id`, який використовується як первинний ключ (`PK`).
- Оренда пов'язується з конкретним клієнтом і автомобілем через `customerId` та `carId`, які є зовнішніми ключами (`FK`).
- Усі `PK` та відповідні їм `FK` мають  тип string.
- Кожен автомобіль пов'язується з однією моделлю через `modelId`, а одна модель може бути пов'язана з декількома автомобілями.
- Усі зв'язки між сутностями в моделі відповідають визначеним кардинальностям: `Customer`  1:N  `Rental`,   `Car`  1:N  `Rental`,   `CarModel`  1:N  `Car`, `Rental`  1:N  `Payment`.
- Оплата пов'язується з орендою через `rentalId`. одна оренда може мати декілька оплат.
- `CarModel.dailyRate` зберігає стандартну ціну оренди за один день, а `Rental.price` — загальну ціну конкретної оренди.
- Дані про марку та модель автомобіля зберігаються в `CarModel`, а `Car` посилається на відповідну модель через `modelId` без дублювання цих даних.
- Одна машина не може мати декілька активних оренд, часові періоди яких перетинаються.
